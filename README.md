# SoundOS

A browser-based modular synthesizer builder: you assemble a patch out of nodes (generators + signal processing), hit **Generate** — and the patch starts oscillating and sounding permanently, in real time, like a hardware modular rig that's powered on and patched. There's no keyboard and no notes — generators start immediately and keep sounding continuously until **Stop** is pressed.

The name is a placeholder — trivial to rename (the `<title>` in `index.html`, and the branding in `#toolbar .brand`).

The oscilloscopes, the Rhythm/Crush/Ring/Gate/Field/Freeze/Comb/Shimmer nodes, the performance buttons (Chance/Stage) and the starter patch with presets are ported by technique, math and topology from `pulse-train-stage-ii.html` and `pulse-train-node-database.html` (`followorbounce.github.io`) — the patch architecture itself (a Web Audio graph + JSON state instead of a fixed set of modules) stayed as modular as it already was in SoundOS. The sound reference is Ryoji Ikeda and the Raster-Noton/Alva Noto label: minimal techno at the intersection of a hard digital click (Crush/Gate/Rhythm) and a soft, near-infinite texture (Freeze/Shimmer/Space).

## Running it

Needs a local HTTP server (ES modules and AudioWorklet don't work over `file://`):

```bash
cd soundos
python3 -m http.server 8080
# open http://localhost:8080
```

## How it's built

- **`js/nodeLibrary.js`** — the systematized node database. Every node type describes its ports (inputs/outputs), its params, and a `build(ctx)` factory that creates a real Web Audio graph with a uniform contract (`inputs`, `audioParams`, `output`, `setParam`, `dispose`, optionally `gateOn`/`gateOff`). Adding a new node type means adding one object to this file; the menu and the engine pick it up automatically.
- **Generators**: Oscillator, LFO, Noise, Envelope (ADSR as a CV source — like in a real modular rig, not built into a VCA), **Rhythm** — a self-clocked impulse/click generator (a sawtooth "clock" through a decaying WaveShaper curve gates highpassed noise — the sharp attack comes from the sawtooth's own hard wrap on every cycle), needed for rhythm/beats with no keyboard and no notes.
- **Processing**: Filter, Amp/VCA, Mixer, Delay, Distortion, Reverb, **Math**, Output, plus the full set of Character/Time nodes from Pulse Train: **Crush** (bit reduction, `Q(x,b)=round(x·2^(b-1))/2^(b-1)` via a WaveShaper staircase), **Ring** (true 4-quadrant ring modulation — the carrier drives the `gain` param directly), **Gate** (rave gate: a sawtooth clock through a threshold WaveShaper curve produces a variable-duty rectangular pulse subtracted from the base gain), **Field** (stepped stereo pan — the same quantizing staircase as Crush, just applied to a control signal instead of audio), **Freeze** (a delay with feedback around ~98% — the same circuit as Delay, stretched almost to infinity), **Comb** (the same feedback delay at millisecond-scale time — a metallic resonator; the `Freq` knob sets `delayTime=1/freq`, reads as a pitch), **Shimmer** (chorus — a short ~18ms delay whose `delayTime` is wobbled by a slow sine LFO), **Null** (a passive unity-gain pass-through with no knobs at all — a neutral junction for landing several chains on before Output, same idea as a "null"/"mult" utility on a real rack; always renders in Compact's tightest layout regardless of the global toggle, since it has nothing on it worth compacting).
- **Video**: **Video Output** — not an audio sink, but a canvas: up to 4 inputs, each tapped by its own `AnalyserNode`. If 2+ signals are connected, they're first combined with the same arithmetic as the Math node (add/sub/mul/min/max/avg), then the resulting waveform is drawn onto a `<canvas>` with a configurable resolution (320×240 … 1920×1080) and can go fullscreen via the **⛶ Fullscreen** button.
- **`js/canvas.js`** — the visual editor: nodes are compact HTML blocks on a pannable canvas, cables are SVG curves. **Zoom** (0.3×–2.5×): Ctrl/Cmd + mouse wheel zooms toward the cursor, the **−**/**+** toolbar buttons zoom toward the center of the visible area, clicking the percentage resets to 100%. Implemented as a CSS `transform:scale()` on `#canvas-inner` around its `(0,0)` corner — node and cable coordinates stay in "logical" space (as if there were no zoom), so anywhere a raw mouse delta in screen pixels gets combined with a logical coordinate (dragging a node, drawing a cable, placing a new node from the menu) that delta is divided by the current zoom — otherwise, at zoom ≠ 100%, a node/cable drifts away from the cursor. Node dragging. **Connecting a cable** — you can start dragging from anywhere on the jack's whole row (not just the 11px dot — the label works too), and releasing close enough to the target jack is enough, not exactly on it: while dragging, the nearest `in` jack within a 24px radius of the cursor lights up and "snaps" the cable's end to it — release nearby and the connection still lands. Same principle as disconnecting. **Disconnecting a cable** works two ways: clicking anywhere near the cable (an invisible wide band on top of the thin visible line catches the click, no need to hit the 2px line exactly), or the explicit **×** button in a circle right at the cable's midpoint. An important layering detail: the cables' SVG is explicitly raised above `#nodes-layer` via `z-index` (like `#cableSvg{z-index:5}` in Pulse Train) — without this, clicks on a cable passing under a node card would never reach the SVG at all, because the card would intercept them first. **Every** node with an output always shows an oscilloscope of its own signal at the bottom of its card (not a toggle button — always on, like in Pulse Train — Stage II), tapped through a dedicated `AnalyserNode` in the engine; the **Scopes: Wave/Spectrum** toggle in the toolbar switches every oscilloscope at once between waveform and spectrum. The **Compact** button doesn't just hide the oscilloscopes with a CSS class: `renderNode()` doesn't create the oscilloscope canvas at all in this mode (it isn't rendered — so it isn't recomputed every frame either), and each node card gets a `.compact` class directly, not an ancestor class on `<body>` — deliberately, so it doesn't depend on CSS cascade/specificity. In this mode every node is rebuilt into its tightest possible layout (less padding, no description line, smaller knobs/jacks/switches, but not so small they're hard to hit with a mouse) — for performance use, where many nodes need to fit on screen at once. Turning Compact on also **repacks the board**: every node snaps into a tight grid (clustered into columns by its current x, then stacked by y within each column, at fixed close spacing) instead of keeping its old, wide-open gaps; the pre-compact positions are remembered and restored exactly when Compact turns back off. Two nodes ignore the Compact toggle entirely, in opposite directions: **Video Output**'s canvas is untouched either way (it isn't monitoring, it's the node's actual function, and a hidden element can't go fullscreen), and **Output** always shows its scope regardless of Compact (it's the master signal, always worth seeing) even though it has no output port of its own and would never otherwise qualify for one. **Null** goes the other way and is permanently compact no matter the toggle — it has nothing on its body compacting would hide anyway.
- **Bypass button** (a circular footswitch next to the name) — on **every** node, including Video Output. For effects with a separate input node (Delay/Distortion/Reverb/Crush/Ring/Gate) it's a real dry/wet bypass: the signal routes around the processing without cutting out. For generators and single-node processors (Filter/Amp/Mixer/Math, where `in` and `output` are physically the same AudioNode) bypass just mutes the node's contribution — the same way a source with nothing patched into its own `in` goes silent when bypassed in Pulse Train. On Video Output the button doesn't touch audio — it just pauses the canvas render. Toggles live, no need to press Generate again.
- **Performance buttons in the toolbar**: **⚄ Chance** — shuffle every knob on the board to a random value within its range, live, even while the synth is already playing; **⛶ Stage** — fullscreen mode for a live set.
- **`js/menu.js`** — the systematized node menu (generators/processing, search). On desktop, picking a node opens a grid — you can explicitly choose the row and column to place it in; on mobile a node is placed automatically.
- **`js/audio/engine.js`** — compiles the visual patch into a single, continuously-running Web Audio graph: generators start as soon as they're built (same as every node in nodeLibrary already does), **Generate** just connects the graph to the master bus and fades it in, **Stop** fades it out and tears the graph down. No per-voice cloning and no notes — the sound is continuous as long as the patch is connected to Output.
- **`js/audio/worklets/mathProcessor.js`** — the Math node runs through an AudioWorklet: native Web Audio can only *sum* signals arriving at a param, so `multiply`/`min`/`max` (an "OR"-like combination) needs real sample-by-sample math.
- **The starter patch** (`seedDemoPatch` in `js/main.js`) is built from 14 nodes — the same grouping (Sources/Character/Time/Master) as the default rack in Pulse Train — Stage II, plus one addition: Tone/Tone II are two Oscillators, then Rhythm, LFO (unpatched, same as in the reference — just sitting ready), Crush, Ring, Field, Drive (=Distortion), Freeze, Comb, Shimmer, Space (=Reverb), a **Null** junction, and Output. Laid out left to right — Sources, then Character, then Time, then Null, then Output — so signal flow reads the way it's patched instead of top to bottom. The wiring: `tone→crush→comb→space→null`, `tone→ring→field→null`, `rhythm→null`, `tone2→freeze→null`, `tone2→drive→shimmer→null`, then `null→output` — all five chains land on the Null node rather than summing directly on Output's own `in`, a real pre-master junction point (several sources into one `in` port sum regardless, so this is a design choice, not a technical requirement). The one simplification versus the reference: our Oscillator has a single output, not two (`out`/`out2` like Tone) — so wherever the reference uses the second output, the first one is just duplicated here.
- **`js/presets.js`** — 9 tuning presets ported from `PRESETS` in Pulse Train — Stage II (Unison Beat, Perfect Fifth, Golden Ratio, Harmonic Series, Tritone, Pythagorean Comma, Critical Band Roughness, Fibonacci Pulse, Driven Shimmer). Each one's mathematical core — the exact frequency ratio between Tone/Tone II — is carried over verbatim; the secondary knobs (Rhythm/Crush/Comb etc.) are re-tuned for these differently-built versions of those nodes rather than copied number-for-number, since the DSP isn't identical. Presets apply by role (`tone`, `tone2`, `crush`, …), not by node id, so they keep working as long as the starter rack hasn't been manually renamed/rebuilt; the picker is `#preset-select` in the toolbar.
- **Undo/redo** (`Ctrl/Cmd+Z`, `Ctrl/Cmd+Shift+Z` or `Ctrl/Cmd+Y`) — a stack of full JSON snapshots of the patch in `js/state.js`, not a field-level diff, deliberately for simplicity. Adding/removing a node, adding/removing a cable, Clear and Import checkpoint themselves — those are already atomic, one-shot actions. Dragging a node, turning a knob, Chance and presets do **not** checkpoint on every `mousemove`/every param in a batch (otherwise one Ctrl+Z would only undo one pixel of movement); the checkpoint there is taken once at the start of the gesture/batch — node and knob drags on `mousedown`, Chance and presets before the whole cycle.
- **Speed** (a toolbar slider, −2…+2 octaves, `speed = 2^value`) — a global varispeed for the whole network, like speeding up or slowing down tape: every param in `nodeLibrary.js` can carry an optional `scale: 'hz'` tag (pitches and rate-CVs — Oscillator.freq, LFO/Rhythm/Gate/Field/Shimmer.rate, Filter.frequency, Ring/Comb.freq) or `scale: 'time'` (durations — Envelope.attack/decay/release, Delay/Freeze.time, Reverb.size). `engine.setSpeed()` multiplies the first group and divides the second by one shared factor across every live node at once, with no graph rebuild — as smooth as any other knob. Untagged params (mix, resonance, bits, all the levels) are left alone.

## Patching philosophy

Any output can be plugged into any input — whether that's another node's audio input or straight into a param (modulation). There are no restrictions by signal type: an oscillator can feed directly into another oscillator's frequency (FM), and an LFO can feed a Math node, where its signal combines with another (add/subtract/multiply/min/max/average) before going on to modulate a filter's cutoff frequency.

## Known simplifications (MVP)

- A single graph, no polyphony — the Envelope node opens once on **Generate** (and holds its sustain level forever) rather than per note: there's no keyboard and no concept of a "note" in the project at all right now.
- Patch changes (a new/deleted node, a new/deleted cable) while playing **rebuild the whole graph from scratch** (live, without needing another Generate press — otherwise, say, deleting the Output node would have no effect on audio that's already playing). This is an honest but blunt tool: rebuilding restarts every oscillator's phase and every envelope's held note, so there can be a short click/reset on every live patch edit — there's no surgical, rest-of-the-graph-untouched re-patching yet. Bypass and knob params are the exception: they change live with no rebuild and no clicks.
- Export/Import is JSON-patch only (the graph structure), not a standalone HTML player.
- Presets are tied to the starter rack's roles (`tone`, `crush`, `space`, …) — if the patch is deleted or entirely rebuilt, the toolbar presets become a no-op for the missing roles (no error, they just skip whatever isn't there).

## Ideas for later

- Exporting a patch to a standalone HTML file that plays the preset with no editor.
- Snap-to-grid for ordinary dragging.
- Surgical live re-patching (add/remove a single cable or node with no rebuild and no click on the rest of the graph) — right now any structural change on the fly rebuilds everything.
- MIDI input from a real device as a CV source (frequency/gate) for generators.
